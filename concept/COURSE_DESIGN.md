# Проєкт: OOP C# Курс — Медична Клініка (еталонний домен)

## Загальна ідея

Студент будує **одну живу систему** весь курс. Кожна лаба = окрема гілка `Lab-NN`;
з Лаби 03 кожна додає нову функціональність і зливається в `main` (Лаби 01–02 —
тренажери, не зливаються). Еталонний домен: **Медична Клініка**.
Інструкції для студентів пишуться в **абстрактному вигляді** (Сутність A, Операція, Користувач).
Студент підставляє свій домен (готель, ресторан, аптека тощо).

## Структура репозиторію

**Репозиторій студента** (`oop-course/`) — те, що будує студент:

```
oop-course/

├── oop-course.sln          ← спільне рішення (створюється в Лабі 01)
├── Lab01/                   ← Lab 01: базовий C#, тренажер (гілка Lab-01, не зливається)
├── Lab02/                   ← Lab 02: масиви, тренажер (гілка Lab-02, не зливається)
└── ClinicApp/               ← Lab 03+: головний проєкт, росте весь курс (зливається в main)
    ├── ClinicApp.csproj
    ├── Program.cs          ← єдина точка входу
    ├── Clinic.cs           ← оркестратор (Lab 03)
    ├── Enums/              ← Lab 04
    ├── Models/             ← Lab 03+: Patient, Doctor, Appointment, WorkSchedule; Lab 06+: MedicalRecord…
    ├── GrowablePatientManager.cs  ← Lab 03 (Задача 8)
    ├── Managers/           ← Lab 03+: PatientManager, DoctorManager, AppointmentManager; Lab 06+ …
    ├── Interfaces/         ← Lab 07+

```

**Репозиторій курсу** (цей репо) — довідник: `labs/` (інструкції), `lectures/`,
`concept/` (ці документи), `git-workshop/`, `site/`. Еталонний код тут поки в
теках `sandbox/`, `src/` і на гілках `feature/*` — перейменування під нову схему
(`Lab01/`, `ClinicApp/`) заплановане окремо.

## Git стратегія

### Гілки (репозиторій студента)
```
main                        ← завжди робочий стан; росте з Лаби 03
Lab-01, Lab-02              ← тренажери: push на GitHub, у main НЕ зливаються
Lab-03 … Lab-22            ← кожна відходить від main, зливається назад (--no-ff)
```
*(У цьому репо еталон поки на гілках `feature/*` + `sandbox/*` — окрема задача.)*

### Правила комітів
```
Lab03: project              ← коміт створення проєкту
Lab01 Task01                ← коміт завдання (дві цифри, без опису)
Lab03 Task02
```

### Злиття в main
- ✅ Зливається: якщо в консолі з'являється нова команда або поведінка
- ⏳ Чекає: якщо зміна тільки внутрішня (рефакторинг, валідація)
- ⏳ → зливається разом з наступною лабою

## Структура instructions.md (шаблон)

Кожна лаба: `# Лаба NN — Тема` → `## Мета` → `## Контекст` (+ «Що дозволено» /
«Ваш домен» / «Як користуватися підказками») → `## Крок 1` (гілка + проєкт) →
`## Задача N` × (8 для Лаб 01–03, 4 для Лаб 04+) → `## Перевірка перед здачею` →
`## Питання для самоперевірки` → `## Статус гілки`.

**Кожна `## Задача N`:**

```
### Умова
### Формат вводу        (Лаби 01–02)  |  ### Специфікація класу  (Лаби 03+)
### Приклад(и)          (ввід/вивід або приклад використання API)
### Підказки            — покрокова ПРОЗА, без коду-рішення
📖 Документація         — 2–5 посилань на learn.microsoft.com
### Адаптація до вашого домену   — таблиця відповідників
### Коміт               — git add <файли> ; git commit -m "LabNN TaskYY"
```

**Правила:**
- Гілка: `git checkout main && git checkout -b Lab-NN`.
- Коміти: `LabNN TaskYY` (дві цифри, **без опису**). Проєкт: `LabNN: project`.
- Злиття: Лаби 03+ → `git merge --no-ff Lab-NN`; Лаби 01–02 — лише `push`.
- Підказки описують напрям думки й відсилають до документації, а не дають код.
- ⭐…⭐⭐⭐⭐ — рівень складності задачі.
