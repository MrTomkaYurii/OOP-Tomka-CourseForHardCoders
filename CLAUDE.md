# OOP-Tomka-CourseForHardCoders — правила для Claude

Курс ООП на C# (.NET 10) викладача Юрія Томки: лекції (`lectures/sections/*.md`, сайт
tomka.space), лабораторні (`labs/`), еталонний проєкт «Клініка» (`src/`), схеми (`diagrams/`).

## Спілкування

- Відповідати **українською або російською** — мовою користувача. Ніколи англійською.
- Користувач пише з помилками — не виправляти, зрозуміти суть.
- Користувач добре знає архітектуру, ООП, SOLID, EF Core — базове не пояснювати.

## Схеми (рисунки) лекцій

Лише через пайплайн `diagrams/` — правила, формат spec і процес у **`diagrams/CLAUDE.md`**
(прочитати повністю перед роботою). Коротко: `specs/<id>.yaml` → `make.sh <id> --publish`;
dark → `lectures/_assets/NN-NN/`, bw → `…/book/`, оригінал і старий скрипт → `…/Архив/`.
Старий підхід (PNG через PIL-скрипт у теці розділу) більше не використовується.

Linux / хмара: перед першим запуском `bash diagrams/setup-linux.sh`. Готовий промпт для
хмарної сесії (рисунки розділів 10–21, відновлюваний) — `diagrams/CLOUD_PROMPT.md`.

## Лекції (`lectures/sections/*.md`)

1. **Обсяг теорії не скорочувати ніколи.** Переробка = більше, детальніше, структурованіше.
   Можна додавати підрозділи, приклади, пояснення.
2. **Академічний стиль**: що це, навіщо, як працює — повноцінним текстом, не переліком.
3. **Домен — клініка** (пацієнти, лікарі, прийоми, діагнози, палати). Міняти лише імена
   й сценарії прикладів, не обсяг теорії.
4. **Факти перевіряти кодом** на .NET 10 (`dotnet run файл.cs`) — версії API, винятки,
   поведінка. Знайдена помилка в тексті → виправити з поясненням і перелічити у звіті.
5. **Runnable-блоки** (`` ```csharp run ``) мають бути самодостатніми і запускатися:
   - `using System;` і повні визначення класів у блоці;
   - **top-level код — зверху, класи — знизу** (інакше CS8803);
   - вивід лише `Console.WriteLine(string)` — інтерполяцією: `$"Вік: {age}"`, а не
     `Console.WriteLine(age)` (Blazor-раннер на сайті не підтягує інші перевантаження);
   - дробові числа з рядків — `CultureInfo.InvariantCulture` (українська локаль: кома).
   Перевірка: витягнути всі повні приклади розділу і запустити кожен.
6. **Аналіз перед написанням**: таблиця «що є → що покращити», потім текст.
7. Посилання на схему в тексті («п'ять кроків з діаграми») має відповідати схемі.

## Лабораторні і `src/`

- Кожна лаба використовує **лише конструкції з лаб ≤ поточної** — контракт у
  `concept/CONCEPTS_BY_LAB.md` (не лекції!). Generic-колекції — не раніше Lab 09,
  LINQ — не раніше Lab 14, `?.`/`??` — не раніше Lab 04.
- Перед новою лабою читати `concept/COURSE_DESIGN.md`, `concept/CONCEPTS_BY_LAB.md`,
  `concept/CODEBASE_STATE.md`.
- Переписуючи інструкцію лаби — зберегти стару версію і після переписування звірити
  (токени в бектиках, посилання, таблиці, пункти чекліста), що нічого не загубилось.

## Git

- Рисунки й виправлення тексту — окремими комітами.
