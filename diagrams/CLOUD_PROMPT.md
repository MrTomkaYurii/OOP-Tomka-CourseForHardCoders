# Промпт для хмарної сесії Claude Code: рисунки одного розділу

Скопіюйте текст нижче в нову сесію на claude.ai/code (репозиторій
`MrTomkaYurii/OOP-Tomka-CourseForHardCoders`), замінивши **NN** на номер розділу
(двозначний: `09`, `12`…). Один розділ — одна сесія; розділи можна запускати паралельно.

---

```text
Переробити всі рисунки розділу NN курсу за правилами diagrams/CLAUDE.md і виправити
фактичні помилки в тексті лекцій цього розділу. Працюй автономно, без уточнюючих питань;
спірні рішення приймай сам і фіксуй у звіті. Відповідай українською.

0. Прочитай CLAUDE.md у корені і diagrams/CLAUDE.md повністю. Зразки готових
   специфікацій — diagrams/specs/*.yaml (розділи 13 і 14).
1. Оточення: bash diagrams/setup-linux.sh (наприкінці має бути «✓ перевірки пройдено»).
2. Гілка: git checkout -b diagrams/chapter-NN
3. Знайди всі рисунки: grep -n "_assets/NN-" lectures/sections/NN-*.md
   Для кожного (у тому числі якщо PNG не існує — тоді малюй з нуля):
   а) прочитай секцію лекції й старий PNG; склади список змістових помилок старої схеми;
   б) кожен сумнівний факт (версії API, винятки, результати) перевір кодом:
      dotnet run файл.cs у тимчасовій теці поза репозиторієм (наприклад /tmp/check);
   в) напиши diagrams/specs/<ім'я>.yaml: publish dark → lectures/_assets/NN-XX/<ім'я>.png,
      bw → lectures/_assets/NN-XX/book/<ім'я>.png; числа й винятки перевіряй через
      check ({v}, asserts);
   г) cd diagrams && ./make.sh <ім'я>  — виправляй, доки немає жодного ✗;
   д) ОБОВ'ЯЗКОВО відкрий out/dark/<ім'я>.png і out/bw/<ім'я>.png і подивись:
      порожні «діри» в стовпчиках, буквальні [[ ]], обрізаний чи накладений текст,
      баланс стовпчиків. Виправ і повтори (до 5 ітерацій);
   е) git mv старий PNG і gen_diagram.py у lectures/_assets/NN-XX/Архив/,
      потім ./make.sh <ім'я> --publish
4. Тексти лекцій NN-*.md: знайдені фактичні помилки виправ (теорію не скорочувати —
   розширювати з поясненням). Витягни всі повні приклади (```csharp блоки, що
   починаються з using) і запусти кожен — усі мають компілюватися й виконуватися.
5. Допиши в diagrams/REPORT.md розділ «Розділ NN» (таблиця схем і що було не так;
   що виправлено в лекціях) за зразком розділу 13.
6. Два коміти: feat(diagrams): перероблено схеми Розділу NN
               fix(lectures-NN): виправлено фактичні помилки в тексті Розділу NN
   git push -u origin diagrams/chapter-NN і відкрий pull request у main.
7. Прибери сміття (тимчасові файли поза репо, __pycache__). Наприкінці коротко:
   що зроблено, які помилки знайдено, посилання на PR.
```

## Перевірено

Скрипт оточення й рендер перевірено в чистому контейнері `ubuntu:24.04` (draw.io 31.7.0,
.NET 10.0.401): результат збігається з Windows-рендером. Відомі пастки Linux, які вже
враховано: `libasound2t64` для Electron і `--disable-dev-shm-usage` (замалий `/dev/shm`
у контейнерах).

## Після сесій

Кожен розділ приходить окремим PR у `main`. Конфліктів між розділами не буває, бо кожен
пише лише свої `specs/`, свої `_assets/NN-*` і свої лекції. Спільний тільки
`diagrams/REPORT.md`: якщо дві гілки допишуть його одночасно, залиште обидва розділи.
Якщо хмарна сесія змінить генератор (`diagrams/generator/`), такий PR варто переглянути
уважніше: зміна впливає на всі схеми. Після злиття варто перегенерувати все (`./make.sh`)
і переконатися, що жодна вже готова схема не зламалася.
