## Загальні вади старих схем (усі виправлено)

## Виправлення змісту по схемах

**14.1** — «MemberInfo — базовий клас для всіх вище» охоплювало `Assembly`/`Module`, які не є
`MemberInfo` (а сам `Type` — є); різні namespace (`MyNS`/`Med`) → `Med`; `[Test]` у xUnit →
`[Fact]`; стрілки підписано `GetModules()`/`GetTypes()`; `GetType()` — фактичний тип, на `null`
виняток; `Type.GetType` для іншої збірки потребує її імені; `IsClass` — і для делегатів,
`IsAbstract` — і для інтерфейсів; додано `t1 == t2 == t3`, `IsSealed`, `IsPublic`, «ціну
гнучкості»; виправлено «зо інтерфейсом».

**14.2 (нова)** — два виміри фільтра (доступ × рівень) + уточнення; пастка «явні прапорці —
CLR нічого не додає» (`GetMembers(NonPublic)` → 0 членів, перевірено); типові комбінації;
що саме знаходить рефлексія в автовластивості (властивість + 2 аксесори + backing-поле);
`DeclaringType` vs `ReflectedType`.

**14.3** — додано `IsFamily`/`IsAssembly`, `IsSpecialName`; `ParameterType` `Int32&` для
`ref/out/in`; `DefaultValue` = `DBNull.Value`; три винятки `Invoke` перевірено кодом;
`.cctor` — через `t.TypeInitializer` (а не «викликати не можна»); `Activator` з приватним
конструктором — `nonPublic: true`; прибрано вигадані наносекунди.

**14.4** — головне виправлення, таблиця «Що дозволяє SetValue» (перевірено в .NET 10):

| оголошення | SetValue | стара схема і лекція |
|---|---|---|
| `const` | FieldAccessException | ✓ |
| `static readonly` | FieldAccessException | ✓ |
| `readonly` (екземпляра) | **працює** | ✗ «FieldAccessException» |
| `{ get; init; }` | **працює** | ✗ «FieldAccessException» |

Ланцюжок дій скорочено з 5 до 3 кроків (знайти → прочитати → записати).

**14.5** — `Assembly.Load` «з GAC» (у .NET Core GAC немає) → «за ім'ям збірки»; `LoadFile`
— окремий контекст (перевірено); таблиця способів завантаження × контекст × Unload ×
залежності; ключова пастка: **той самий тип у двох ALC — різні типи** (перевірено), тому
крок 1 патерну Plugin — «контракт у спільній збірці», а не «у host-збірці».

**14.6** — пастки `inherit`: для `PropertyInfo`/`EventInfo` параметр ігнорується, потрібен
`Attribute.GetCustomAttributes(prop, true)`; атрибути інтерфейсу не переходять на клас
(обидва перевірено); типові `AllowMultiple = false`, `Inherited = true` (перевірено);
`[Serializable]` — лише для застарілої бінарної серіалізації; вигадані `[Singleton]`/
`[Scoped]` у «DI scanning» замінено реальними атрибутами ASP.NET Core / xUnit / EF Core.

## Помилки в тексті лекцій — виправлено

Кожен факт перевірено кодом на .NET 10; усі 13 повних прикладів розділу компілюються й
виконуються після правок. Теорію не скорочено — виправлені місця розширено поясненнями.

1. **14.4**, const vs readonly: «`SetValue` на `readonly` кидає `FieldAccessException`» →
   таблицю доповнено колонкою `SetValue`; пояснено, чому `readonly` екземпляра записується,
   а `static readonly` (.NET Core 3.0+) і `const` — ні; прибрано вигаданий «хак з
   `RuntimeFieldHandle`».
2. **14.4**, init-only: «`SetValue` кидає `FieldAccessException`» → `SetValue` працює;
   пояснено модифікатор `IsExternalInit`, як відрізнити `init` від `set`; прибрано
   непотрібний «обхід через backing field» і хибну згадку Moq/NSubstitute.
3. **14.4**, приклад ObjectCloner: `FormatterServices` (застарілий, SYSLIB0050) →
   `RuntimeHelpers.GetUninitializedObject`; виправлено «єдиний легальний спосіб обійти init».
4. **14.3**, Activator: «приватний конструктор не підтримує» → `nonPublic: true` для
   безпараметрового, `MissingMethodException` для решти.
5. **14.3**, `.cctor`: «не може бути викликаний через `Invoke`» → викликати можна, але CLR
   повторно його не виконує; додано `Type.TypeInitializer`.
6. **14.3**, «security-check» при `Invoke` і таблиця з наносекундами для .NET 8 → відносна
   вартість, пояснення, звідки вона береться, порада міряти BenchmarkDotNet; CAS у .NET
   Core немає.
7. **14.3**, `FormatterServices.GetUninitializedObject` → `RuntimeHelpers…` з поясненням.
8. **14.5**, `Assembly.Load` «з GAC» → у .NET Core/5+ GAC немає; додано, де саме шукає.
9. **14.6**, «`ParameterInfo` — нащадок `MemberInfo`» → спільний інтерфейс
   `ICustomAttributeProvider`; додано пастки `inherit` для `PropertyInfo`/`EventInfo` та
   інтерфейсів.
10. **14.4**: «п'ять кроків з діаграми» → «три кроки» (нова схема).

| 10.6 | `observablecollection-event-flow` | «Remove(id)» — метод приймає елемент, не id; бракувало дії Move (лекція перелічує 5); діагональні стрілки; не показано, що для Reset OldItems = null і що є індекси NewStartingIndex/OldStartingIndex. |
| 10.7 | `ienumerable-foreach-decomposition` | IEnumerator<T> показано з MoveNext/Reset/Dispose як власними членами — насправді він оголошує лише Current, решта з IEnumerator та IDisposable; не сказано, що foreach працює за патерном (метод GetEnumerator), а Reset в ітераторах yield кидає NotSupportedException. |
| 10.8 | `yield-lazy-execution` | підписи стрілок MoveNext/yield return накладалися один на одний (нечитабельно), текст унизу обрізано; «// кінець — yield break» хибно (метод просто завершується, yield break не потрібен); не показано, що Коваль пропускається між паузами, повторний запуск foreach і відкладену перевірку аргументів. |
