# Схеми курсу: пайплайн spec.yaml → draw.io → PNG/PDF

Усі нові й перероблені схеми лекцій робляться **тут**, а не окремими PIL/HTML-скриптами
в `lectures/_assets/**`. Одна команда генерує, рендерить, перевіряє і (за потреби)
публікує схему в лекцію.

```
diagrams/
  CLAUDE.md          цей файл — правила стилю і процесу
  themes.yaml        палітри dark / light / bw (кольори — ТІЛЬКИ тут)
  generator/         Python: spec.yaml → .drawio, експорт, перевірки
  specs/<id>.yaml    опис схеми (без координат і кольорів) — ЄДИНЕ, що пишеться руками
  REPORT.md          звіт: що виправлено у схемах і що знайдено в лекціях
  out/               згенероване (.gitignore): <тема>/<id>.{drawio,png,pdf}, check/<id>/
  make.ps1 / make.sh одна команда на все
```

**Куди потрапляє результат** (ключ `publish:` у spec, копіюється з `--publish`):

| тема | куди | навіщо |
|------|------|--------|
| `dark` | `lectures/_assets/NN-NN/<id>.png` | сайт (те саме ім'я, що в `![…](…)` лекції) |
| `bw`   | `lectures/_assets/NN-NN/book/<id>.png` | книга / Word-експорт (білий фон, ч/б друк) |
| `light`| лише `out/light/` | за потреби (кольоровий друк) |

Оригінал, що переробляється, і його старий скрипт — у `lectures/_assets/NN-NN/Архив/`
(`git mv`, щоб зберегти історію). Окремої теки з копіями оригіналів немає.

## Запуск

```powershell
.\make.ps1                          # усі схеми, усі теми, перевірки
.\make.ps1 reflection-type          # одна схема
.\make.ps1 reflection-type --publish  # + скопіювати PNG у лекцію (ключ publish: у spec)
python -m generator --themes dark --no-export   # швидко: лише модель і перевірки
```

Код повернення ≠ 0, якщо хоч одна перевірка не пройшла. `--publish` копіює лише за
повного успіху.

## Оточення

- **draw.io desktop** (`winget install JGraph.Draw`; Linux — .deb/AppImage, без дисплея
  генератор сам додає `xvfb-run`). Шлях можна задати змінною `DRAWIO`.
- **JetBrains Mono** у системі (fallback — Fira Code). Без шрифту генератор зупиняється:
  інакше draw.io тихо підмінить шрифт і всі розміри поїдуть.
- Python 3.11+: `pip install pillow pyyaml`. Для перевірки коду — .NET SDK 10.

## Правила стилю

1. **Шрифт один — JetBrains Mono**, лігатури вимкнено (`==` не стає `═`).
   Шкала (px / висота рядка): title 28/40 · subtitle 15/24 · heading 18/28 ·
   boxtitle 15/24 · code 14/22 · text 14/22 · small 13/20.
2. **Сітка 8 px.** Усі блоки й розділи мають x, y, ширину й висоту, кратні 8.
   Відступи: поле 32, між розділами 24, всередині розділу 16, блок 16×12.
3. **Розміри — з реальної ширини тексту** (Pillow міряє той самий TTF у кеглі 1000 і
   масштабує: хінтинг Pillow на малому кеглі округлює advance і дає похибку до 5 %).
4. **Стовпчик = одна ширина.** Діти розділу розтягуються на його ширину; ряди `flow`
   мають однакові ліві/праві блоки й однакові стрілки; `row: {equal: true}` — рівні блоки.
5. **Стрілки** — лише горизонтальні або вертикальні, прив'язані до блоків
   (source/target + точки виходу), підпис над горизонтальною стрілкою по центру,
   праворуч від вертикальної.
6. **Підсвітка C# — ролями**, а не кольорами: `keyword type method string number
   comment plain changed`. Токенізатор сам розставляє ролі; фрагмент `[[…]]` у коді
   отримує роль `changed` (виділення зміни: жирний + підкреслення). Нові імена типів
   домену перелічуйте в `types:` специфікації.
7. **Типи блоків:** `box` — звичайний, `box_accent` — головне поняття (1–2 на схему),
   `box_muted` — примітка (пунктир), `panel` — розділ.
8. **Теми:** `dark` — сайт (фон #111413, м'ятні рамки й заголовки #76c7ad); `light` —
   друк/світла тема, той самий характер; `bw` — лише чорний/сірий/білий: ключові слова
   жирні, коментарі курсивні, головне поняття — товста рамка, примітки — пунктир.
9. **Контраст** WCAG: текст ≥ 4.5:1 до заливки свого блока (великий ≥ 3:1), рамки
   розділів/акцентів і стрілки ≥ 3:1 до фону.
10. **Типографіка (автоматично в прозі):** апостроф `ʼ`, тире `—` з пробілами, лапки
    «ялинки», `…`. У коді навпаки — типографські лапки замінюються на ASCII з
    попередженням.
11. **Мова написів — українська.** Код — робочий C#, що компілюється (див. `check:`).

## Специфікація (specs/<id>.yaml)

```yaml
id: my-diagram
title: "Заголовок схеми"
subtitle: "Одне речення: що показує схема"
types: [Patient, Doctor]          # домен для підсвітки
body:                             # вузли зверху вниз
  - row: { gap: 24, children: [ panel…, panel…, stack… ] }
  - panel:
      heading: "Розділ"
      gap: 16                     # необов'язково
      children:
        - box:   { title: "1 · `typeof(T)`", tag: "компіляція", kind: box,
                   code: "Type t = typeof(Patient);", notes: ["примітка"], text: ["рядок"] }
        - note:  { text: ["пунктирна примітка з `кодом`"] }
        - text:  { text: ["просто підпис"] }
        - chain: { align: left,                                           # кроки з кодом — left
                   nodes: [ {title: "1 · крок", lines: "var x = 1;", sub: ["примітка"]},
                            {title: B, via: "GetX()", check: "_ = a.{};", kind: box_accent} ] }
        - flow:  { caption: "…", check: "_ = {};", right_code: false,   # праворуч — текст
                   rows: [ {left: "t.GetMethods()", label: "опц.", right: "масив методів"} ] }
        - kv:    { check: "_ = {};", columns: ["ключ", "значення", "…"],  # N колонок, заголовок опц.
                   key_code: true,                                          # false — 1-ша колонка текстом
                   groups: [ {heading: "…", check: skip,                    # група може вимкнути перевірку
                              rows: [["t.Name", "`\"Patient\"`"], ["", "продовження рядка"]]} ] }
        - row:   { equal: true, gap: 16, children: [ box…, box… ] }
        - stack: { gap: 24, children: [ panel…, panel… ] }
check:                            # перевірка коду зі схеми
  usings: [System, Med]
  context: |                      # змінні, які схема мовчки використовує (t, asm…)
    Type t = typeof(Med.Patient);
  asserts: |                      # твердження схеми як код: якщо схема бреше — збірка падає
    Assert(t.Name == "Patient", "Name");
  types: |
    namespace Med { public class Patient { } }
publish:                          # куди копіювати PNG при --publish (від diagrams/)
  dark: ../lectures/_assets/NN-NN/my-diagram.png
```

У тексті `` `…` `` — інлайн-код (підсвічується); `[[…]]` усередині коду — роль `changed`
(виділити головне, напр. `` `[[FieldAccessException]]` ``). Блоки `code:` і `lines:` ланцюжка
потрапляють у перевірочний проєкт як інструкції (у порядку spec); `flow`/`kv`/`via` — як
вирази через шаблон `check` (`{}` = текст комірки), **після** всіх інструкцій. Псевдосигнатури
(`GetValue(obj)`) — у групі з `check: skip`. `using static …` у `check.usings` дозволяє писати
`Public | Instance` без префікса й однаково перевіряти це.

## Процес (обов'язково, до 5 ітерацій)

1. **Аналіз змісту** оригіналу як викладач C#: помилки, неточності, невідповідності
   лекції → таблиця «що є → що виправити». Показати користувачу, якщо зміни суттєві.
2. Написати `specs/<id>.yaml` з `publish:` (dark → лекція, bw → `book/`).
3. `.\make.ps1 <id>` — генерація трьох тем + автоматичні перевірки:
   сітка, вкладеність, перетини блоків/текстів, текст у рамці (модель **і** піксельна
   перевірка рендеру — смуга відступу біля рамки має бути чистою), рівні ширини
   стовпчиків, рівні стрілки, прив'язка стрілок, контраст, розмір/фон рендеру,
   ч/б без кольору; C#-проєкт `dotnet run` → `CHECK OK`.
4. **Відкрити PNG кожної теми й подивитися** (Read): рівні відступи, симетрія,
   стрілки не торкаються тексту, нічого не обрізано, кирилиця й `ʼ` на місці, ієрархія
   заголовків читається, немає порожніх «дір» у стовпчиках.
5. Відхилення → **виправити генератор** (не координати однієї схеми — їх немає) або
   зміст специфікації → повторити з п. 3.
6. Старий PNG і скрипт — `git mv` у `lectures/_assets/NN-NN/Архив/`; потім `--publish`.
7. Якщо в тексті лекції знайдено фактичну помилку — **не правити мовчки**: записати в
   `REPORT.md` і повідомити користувача. Правити лекцію можна лише там, де вона прямо
   посилається на схему («п'ять кроків з діаграми»).
8. Прибрати сміття: тимчасові файли, `__pycache__`, пробні скрипти.

Порожнє місце в коротшому стовпчику генератор прибирає сам: зайву висоту забирає
останній «гнучкий» нащадок — таблиця `kv` (віддає рядкам, решту — останній групі) або
ланцюжок `chain` (подовжує стрілки); стек розділів ділить її між розділами;
`stack: {spread: true}` рівномірно розсуває блоки (за замовчуванням вимкнено).
Якщо стовпчики все одно сильно різні — **переставте зміст** (перенесіть розділ, стисніть
ланцюжок, додайте корисний рядок із лекції), а не додавайте «повітря».

Співвідношення сторін друкується для кожної схеми. Для ілюстрацій лекцій прийнятно
1.15–2.0; 16:9 (1.78) обов'язкове лише для слайдів.

факти кодом, написати spec, прогнати `make`, переглянути PNG, архівувати оригінал,
опублікувати, доповнити `REPORT.md`, закомітити.
